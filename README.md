# Лабораторная работа №5. MySQL: индексы, права пользователей, изоляция транзакций

Тема: «Creating a system for secure and efficient management of a student academic database»
(«Студенттердің оқу деректер қорын қауіпсіз және тиімді басқару жүйесін құру»).

База данных: `hospital_db` (в методичке `university_db`). Сервер: MySQL 8.0.

## Файлы

| Файл | Назначение |
|---|---|
| `черновой.sql` | Полный перезапускаемый скрипт: таблицы, данные, индексы, транзакции, представления, пользователи |
| `README.md` | Эта документация |

## 1. Таблицы и связи

- Три таблицы: `students` (студенты), `subjects` (предметы), `grades` (оценки).
- `grades` связана с остальными двумя внешними ключами (`FOREIGN KEY`): нельзя поставить оценку несуществующему студенту или предмету.
- Связь «многие ко многим»: у студента много предметов, у предмета много студентов, `grades` их соединяет.

## 2. Индексы

- Индекс ускоряет поиск, как оглавление в книге: без него MySQL читает все строки.
- `EXPLAIN` показывает план запроса. Без индекса `type = ALL` (полный перебор), с индексом `type = ref`, а `rows` уменьшается.
- Созданы индексы:
  - `idx_grade_value` для поиска по оценке;
  - составной `idx_student_subject (student_id, subject_id)` для поиска по паре полей;
  - `idx_subject_name` для поиска по названию предмета.
- В конце `idx_grade_value` удалён, и `EXPLAIN` снова показывает полный перебор.
- На 5 строках разница почти не видна, на больших таблицах она значительная.
- Недостаток индексов: они занимают место и замедляют `INSERT`/`UPDATE`/`DELETE`.

## 3. Уровни изоляции транзакций

- Изоляция определяет, что одна транзакция видит из изменений другой.
- По умолчанию в MySQL `REPEATABLE-READ`: повторное чтение внутри транзакции даёт те же данные.
- Переключали на `READ COMMITTED` (видны только зафиксированные чужие изменения) и обратно. Уровень проверяется через `SELECT @@transaction_isolation;`.

## 4. Транзакции и блокировки

- `ROLLBACK`: `UPDATE` поставил 70, откат вернул 90.
- `SELECT ... FOR UPDATE` блокирует строку до конца транзакции, другие сессии не могут её изменить.
- `COMMIT` сохраняет изменения и снимает блокировку.
- Эксперимент с двумя окнами (`sudo mysql` в двух терминалах):

| Окно | Команда | Результат |
|---|---|---|
| 1 | `START TRANSACTION; SELECT * FROM grades WHERE grade_id = 1;` | видна оценка 90, транзакция открыта |
| 2 | `UPDATE grades SET grade_value = 99 WHERE grade_id = 1;` | выполняется сразу, обычный `SELECT` не блокирует |
| 1 | повторный `SELECT` | всё ещё 90 (снимок `REPEATABLE READ`) |
| 1 | `UPDATE grades SET grade_value = 88 WHERE grade_id = 1;` | строка заблокирована |
| 2 | `UPDATE grades SET grade_value = 77 WHERE grade_id = 1;` | ожидание (блокировка строки); через ~50 с `ERROR 1205` |
| 1 | `COMMIT;` | окно 2 продолжает работу |

## 5. Представления (VIEW)

- Представление — сохранённый запрос, «виртуальная таблица».
- `public_student_grades`: фамилия, имя, предмет и оценка, без возраста и email.
- `teacher_average_grades`: средняя оценка каждого студента (`AVG` + `GROUP BY`).
- Смысл: пользователю даётся доступ не к таблицам, а к представлению с нужными колонками.

## 6. Пользователи и права

Принцип наименьших привилегий: каждому только то, что необходимо.

`student_user`:
1. `SELECT` на всю базу, затем добавлен `UPDATE` на `grades`.
2. Оба права отозваны (`REVOKE`).
3. Оставлен только `SELECT` на `public_student_grades`.

`teacher_user`:
- `SELECT` на `students`;
- `SELECT`, `UPDATE` на `grades`;
- `SELECT` на `teacher_average_grades`;
- `DELETE` не выдаётся.

Проверка прав: `SHOW GRANTS FOR 'имя'@'localhost';`

## Запуск

Скрипт перезапускаемый: в начале удаляет представления и таблицы и создаёт их заново (индексы удаляются вместе с таблицами). Данные в этих таблицах будут сброшены.

Команды `CREATE USER`, `GRANT` и `SHOW GRANTS FOR` требуют прав администратора, поэтому запускать удобнее на сервере:

```bash
scp черновой.sql korgen@77.240.38.105:~/lab5.sql
ssh korgen@77.240.38.105
sudo mysql -t < lab5.sql
```

Пошаговое выполнение лабораторной: войти в `sudo mysql`, выполнять блоки по порядку. Шаг 9 (проверка отказа в записи) выполняется под `student_user`:

```bash
mysql -u student_user -p hospital_db
```

Тестовые учётные записи (только для учебной базы): `student_user` / `Student123!`, `teacher_user` / `Teacher123!`.

## Проверка прав под пользователями

`student_user`:

```sql
SELECT * FROM public_student_grades;   -- работает
SELECT * FROM grades;                  -- ERROR 1142: SELECT denied
UPDATE grades SET grade_value = 100 WHERE grade_id = 1;   -- ERROR 1142: UPDATE denied
```

`teacher_user`:

```sql
SELECT * FROM students;                -- работает
UPDATE grades SET grade_value = 91 WHERE grade_id = 1;    -- работает
UPDATE students SET age = 25 WHERE student_id = 1;        -- ERROR 1142: UPDATE denied
SELECT * FROM subjects;                -- ERROR 1142: SELECT denied
```

## Частые ошибки

| Ошибка | Причина | Решение |
|---|---|---|
| `#1146 Table 'students' doesn't exist` | таблица не создана | выполнить блок `CREATE TABLE` |
| `#1061 Duplicate key name` | индекс уже есть после прошлого запуска | запустить скрипт целиком (он сбрасывает таблицы) |
| `#1227 ... CREATE USER` | нет прав администратора | выполнять в `sudo mysql` |
| `#1142 ... table 'user'` при `SHOW GRANTS FOR` | у `korgen` нет доступа к `mysql.user` | выполнять в `sudo mysql` |
| `ERROR 1205 Lock wait timeout` | ожидание блокировки строки | завершить транзакцию в другом окне (`COMMIT`/`ROLLBACK`) |

## Ответы на индивидуальное задание, п. 10

Нельзя давать все права сразу: пользователь сможет читать чужие данные, менять оценки, удалять таблицы и выдавать права другим. Любая ошибка или взлом учётной записи тогда затрагивает всю базу. Минимальные права ограничивают ущерб.
